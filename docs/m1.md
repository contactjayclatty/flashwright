# M1 device layer

Milestone M1 is the device layer: platform-tools policy, an argv process runner, scan and property reads, slot and lock rules, mode waits, and a Windows USB driver classifier. The wizard UI is later work.

Crates:

- `flashwright-proc` runs an absolute program and an argument vector. It refuses shells and batch files.
- `flashwright-tools` classifies platform-tools, checks a zip SHA-1, and will not restart a foreign adb server unless the user confirms.
- `flashwright-device` scans, reads props, and waits for a mode.
- `flashwright-winusb` classifies a Google USB node. Off Windows the host probe reports that the host is unsupported.
- `flashwright-core` is the session façade. It does not flash.
- `xtask check` rejects shell program names in product source, write-class call sites outside the device crate, and a missing AGPL heading.

## What is mocked

adb and fastboot are `ScriptedRunner`. No phone, no real adb, and no real fastboot is contacted. USB status is classified from fixtures. The Windows SetupAPI enumerator is compiled for the Windows target and is not run here. `SystemRunner` is exercised with `/bin/echo` and `/bin/sleep` on Linux.

## Known gaps

- No device was available, so platform-tools 37.0.1 stays a candidate. The shipped allow list is empty and writes stay off. The published zip SHA-1 is `e03e78b1d80b396f1c3358e31251cb31740e1110` (`platform-tools_r37.0.1-win.zip`, repository2-3.xml, read 9 Oct 2026). Per-file SHA-256s are not invented.
- The pending-OTA probe is not part of this milestone.
- `init_boot` without root is unverified. A failed or inconclusive `ls` falls back to `data/devices.toml`.
- The SetupAPI problem-code mapping is unverified. Phase 1 detects and explains; it does not install a driver.
- A foreign adb server exposes a host protocol number, not the SDK version. The confirmation text reports that protocol number.
- `ro.boot.verifiedbootstate` `red` is not treated as unlocked. Only `orange` is.
- Upstream device, Magisk, and minimum-bootloader tables were not copied. The Magisk and bootloader tables are empty schemas. `aurora`/`eos` comes from upstream issue 325 and is marked unverified.
- A ProcMon trace was not collected. T1.7 is the runner rejection plus `xtask`.
- `exec-out` returns the full stdout buffer. The runner already streams the pipes.
- The wizard UI and its state machine are out of this milestone.
- payload-dumper-rust, the AOSP proto, and avbtool are not used.
