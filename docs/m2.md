# Factory and OTA packages

Flashwright can open a Pixel factory zip or a full A/B OTA zip, extract `init_boot` or `boot`, and check hashes. The call writes only into the directory the caller names. It does not talk to a phone.

The public entry point is `flashwright_core::firmware::open_package`.

## What is accepted

- A `.zip` package only. `.tar`, `.tgz`, and `.tar.gz` are refused.
- A full OTA: `payload.bin` stored uncompressed, `ota-type` `AB`, and no `pre-build`.
- A factory zip: one nested `image-*.zip`, plus the factory flash script.
- Pixel 9 Pro XL (`komodo`) is an `init_boot` phone. Older phones that have only `boot` use that image. If the phone and the package disagree, extraction stops.
- The LU0 and FIPS regions are refused before anything is extracted.

## Checks

- The package file is hashed and unpacked from the handle the caller already opened. The path is not opened again.
- The package SHA-256 is computed in 1 MiB reads. Progress is reported every 64 MiB.
- The last 8 hex digits in the file name must be a prefix of that SHA-256.
- Google's published SHA-256 is required. A missing or blank value is refused. The comparison is case-insensitive.
- The file name, `android-info.txt` (`require board=`), or OTA `pre-device`, and the phone codename must name the same phone. `eos` and `aurora` compare equal. A codename that is not in the device table is refused. On a factory package this check runs before the inner image zip is copied out.
- The phone codename, build date, and security patch come from the scanned phone. They are not optional fields on the open request, and the image's own patch and date are never caller fields.
- An OTA `init_boot` or `boot` image is copied from `REPLACE` operations in the payload. The partition hash is the SHA-256 in the payload manifest. The extracted image must match it.
- A factory image must pass its CRC-32 and parse as a boot image with an AVB footer. When the package states a security patch or a fingerprint, the footer properties must match. Those property checks are not the age gates.
- G07 reads `os_patch_level` from the extracted boot or init_boot header, on that same output file. G08 reads `ro.build.date.utc` from `system/build.prop` or `vendor/build.prop` in the ramdisk when that file is present. An older value than the phone is refused. If a value cannot be read, that gate is acknowledged in plain wording. It is not treated as a pass and it is not a hard block.
- Reads and writes of images, inner zips, and metadata stop at a fixed cap, before the overflowing chunk is written. Output files are created without following a symlink.
- Free space must cover the inner zip, the extracted image, and 1 GiB.

Copying uses 64 KiB times the worker count. One partition is extracted. The worker ceiling is the smaller of 4 and the host's parallelism.

## Tests

CI uses synthetic packages. The opt-in factory check prints `BLOCKED` and does not run unless `FW_PRIVATE_FIXTURES` is set. Set `FLASHWRIGHT_KOMODO_IMAGE` to a factory zip you already have. `FLASHWRIGHT_KOMODO_SHA256` is the published package checksum when you have it. The check does not print image values. CI leaves the opt-in unset.

A 14 GiB fixture and a multi-gigabyte throughput measurement are not part of CI. The free-space check is a comparison, including a request larger than this volume, and the hash buffer sizes are fixed in code.
