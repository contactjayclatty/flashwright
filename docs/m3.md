# M3 Magisk patch

Milestone M3 plans a Magisk patch and checks the result on the PC.

The phone step is the Magisk app path. The confirm title is "Patch on your phone?". The plan is a catalogue of adb push, shell, and pull steps. Confirming it is what copies files and runs the script. A dry run and a wrong plan code copy nothing.

Komodo (Pixel 9 Pro XL) patches init_boot. A boot image for that phone is refused. A hidden or renamed Magisk app stops with "Hidden or renamed Magisk app isn't supported yet".

The script on the phone is `fl_patch.sh`. It uses fixed paths, sets `KEEPVERITY`, `KEEPFORCEENCRYPT`, and `RECOVERYMODE=false`, and runs the user's own `boot_patch.sh` with the busybox from that user's Magisk app. Magisk is not included in this repository.

After the pull, a PC check runs magiskboot: unpack the patched init_boot, require "Magisk detected" and an `init` entry in the ramdisk, and read `SHA1=` from `.backup/.magisk`. That value must be the full 40-hex SHA-1 of the stock image, and the patched file's SHA-256 must differ. magiskboot is resolved by absolute path and SHA-256. `data/magiskboot.toml` records that it is not bundled.

The stock image comes from the image pipeline through `ExtractedBootImage`. Tests use `SyntheticInitBoot` because that pipeline is separate.

## Tests

From the repository root, with Rust 1.88.0:

```bash
cargo test -p flashwright-magisk
cargo test -p flashwright-core magiskboot
```

Checked locally on Linux with rustc 1.88.0. adb and magiskboot are `ScriptedRunner`. No phone is contacted.

| Check | Result |
| --- | --- |
| Hidden Magisk app | refused, no plan |
| Unconfirmed plan | rejected, nothing spawned |
| Confirmed app patch, three runs | `FL_STOCK_SHA256`, `FL_OUT`, `FL_SHA1` |
| Script failure | work directory removal still runs |
| Komodo init_boot, LU0 / FIPS | init_boot accepted, boot and that region refused |
| Magisk version and `/data` space | known-bad fixture and low `Data-Free` block before push |
| Cache | same stock SHA-1 and Magisk code is offered again after the SHA-1 check |
| PC magiskboot | gzip ramdisk, Magisk init, strict SHA-1; an unknown format fails closed |

A real magiskboot and a real init_boot are opt-in. Set `FLASHWRIGHT_MAGISKBOOT`, `FLASHWRIGHT_MAGISKBOOT_SHA256`, `FLASHWRIGHT_INIT_BOOT`, `FLASHWRIGHT_STOCK_SHA1`, `FLASHWRIGHT_STOCK_SHA256`, and `FLASHWRIGHT_PATCHED_SHA256`. CI leaves them unset.

## What is mocked

Device commands are `ScriptedRunner`. The Magisk app archive in tests is a synthetic zip. The init_boot bytes are synthetic and start with `ANDROID!`.

## Known gaps

- No device was available. The app-method script is not run on a phone here.
- The known-bad Magisk table stays empty. Tests inject a fixture list.
- magiskboot is not bundled, and its hash is not pinned.
- UI Automator is not implemented.
- The image pipeline that extracts a real init_boot is separate. This milestone only consumes `ExtractedBootImage`.
